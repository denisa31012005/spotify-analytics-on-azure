# Gold Layer Overview

The Gold Layer focuses on creating consumption-ready data models, primarily by implementing Slowly Changing Dimensions to provide historical insights and auditability. This layer utilizes the declarative power of Delta Live Tables for automated pipeline management.

## Key aspects about SCD

- **Requirement**: To allow business users to track historical changes in dimension tables (e.g., how an artist's status or a user's subscription tier has changed over time).

- **DLT Solution**: DLT is used to implement both SCD Type 1 (overwriting data for non-critical changes) and SCD Type 2 (creating new rows with effective date ranges for historical tracking).

- **Benefit**: Provides a reliable historical record, ensuring that reports run against the Gold Layer can accurately reconstruct the state of the dimension at any point in the past.

## Implementation: Lakeflow Declarative Pipelines

Instead of manually managing complex Spark `MERGE` statements and checkpointing, I defined the Gold Layer using the declarative DLT framework.

- **DLT Pipeline**: This is the orchestrator that manages the execution and dependencies of the Gold Layer tables.

- **Pipeline Name**: `gold_pipeline`

- **Configuration Location**: The pipeline definitions are stored within the `dlt` folder in my workspace root,adhering to the Lakeflow convention.

- **Cluster Management**: DLT automatically manages the compute resources, ensuring efficient scaling , minimizing the operational burden of running the pipeline.

## Overview of implemented SCDs
The parts presented below define Delta Live Tables pipelines for the tables implementing SCDs using declarative pipeline constructs.I wrote code that reads Silver layer streaming tables, applies quality checks, and automates CDC flows for SCD type 2 or type 1 with Delta Lake.

### DIMUSER
```python
import dlt

# Quality checks on the data (user_id must not be null)
expectations = {
    "rule_1": "user_id IS NOT NULL"
}

# Define a Delta Live Table with expectation checks on streaming source data
@dlt.table
@dlt.expect_all_or_drop(expectations)
def dimuser_stg():
    df = spark.readStream.table("spotify_cata.silver.dimuser")
    return df

# Create an empty streaming Delta Live Table for the dimension
dlt.create_streaming_table(
    name="dimuser",
    expect_all_or_drop=expectations
)

# Create CDC flow for SCD Type 2, tracking changes by 'updated_at'
dlt.create_auto_cdc_flow(
    target="dimuser",
    source="dimuser_stg",
    keys=["user_id"],
    sequence_by="updated_at",
    stored_as_scd_type=2,
    track_history_except_column_list=None,
    name=None,
    once=False
)
```
